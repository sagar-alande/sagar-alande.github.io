Title

How a Large Language Model Is Trained · The Steps, the Resources, and What They Cost

Objective

Build a visual artifact that shows the key steps of training a generative AI model from data collection to deployment. It also had to show the main resources each step uses and compare real models such as GPT-4, Claude, and Llama using the training numbers their developers share.

What is it?

A one-page infographic for a quick overview and a 17-slide presentation for more depth. Both use the same numbers and sources. Every figure traces back to a model card, a technical report, a research paper, or a named estimate.

The Infographic

The one-page poster shows the eight training steps, the four resources, seven model snapshots, and the key insights at a glance. It opens as its own page so you can read it at full size.

Overall Progress

First draft

“DeepSeek-V3 matched Llama 3.1's data with 11× fewer GPU hours.”

The math was right, but the claim left out what the number does not count. The data card also said data alone sets what a model knows.

→
Final version

“DeepSeek-V3 reported 11× fewer GPU hours, helped by sparse experts and FP8. Its count covers only the final run on different chips.”

The data card now says quantity, quality, diversity, filtering, and training methods together shape what a model learns.

I checked every number one by one before submitting. That review changed GPT-4's hardware to a range, added limits to the DeepSeek comparison, and fixed a chart bar that made BLOOM's emissions look about nine times larger than they were.

Key Considerations

The four questions that shaped the content.

Design Choices

Each choice has one job, which is to make the numbers easy to read and hard to misread.

Value

This artifact shows that I can take a complex technical process, check the facts behind it, and present it so a reader with no background can follow it.

The same habits carry straight into my work in financial services, where every number in a report has to hold up.

Trace every numberUse the original source and say where sources disagree
Compare fairlyState what each figure counts before putting two side by side
Show the gapsMark missing data as missing so it never reads as zero
Plan the costKnow that data, compute, energy, and time drive the price of any model

Reflection · What I Learned

Before this activity, I thought of an LLM as one big training run. Now I see it as a chain of decisions about data, compute, energy, and time, and each decision changes both how well the model performs and how much it costs.

  • Pretraining is where the money goes. About 96% of DeepSeek-V3's GPU hours went to pretraining, and alignment shapes behavior at a small cost.
  • More data helps, but quality, variety, filtering, and training methods decide what a model actually learns.
  • Where a model trains matters as much as how big it is. BLOOM and GPT-3 are about the same size, but BLOOM emitted 25 tonnes of CO₂e against 552.
  • Design choices can cut cost. DeepSeek-V3 uses only 37 billion of its 671 billion parameters for each token.
  • Closed models share very little, so many popular cost figures are estimates and need to be labeled that way.
  • Source checking. Tracing each number to a model card, technical report, or paper and checking claims one by one.
  • Fair comparison. Stating what each figure counts, such as final run only or different chips, before comparing models.
  • Information design. Using one color and icon per resource, bar charts for scale, and one headline number per card.
  • Honest labeling. Marking undisclosed values as “Not disclosed” and outside estimates in gray italic text.
  • Revising from feedback. Cutting text and raising font sizes after feedback that the first version felt crowded.
  • Neural network architecture. Pretraining is the same loop I tested in the TensorFlow Playground. The model predicts, the loss measures the error, and the optimizer updates the weights. An LLM just repeats it trillions of times.
  • Loss and overfitting. The evaluation step exists for the same reason I compared training loss with test loss. A model is only useful on data it has not seen.
  • Word embeddings. Tokenizing turns text into numbers, and the model learns an embedding for each token, just like the Word2Vec vectors I explored earlier.

“Training an LLM is a chain of decisions about data, compute, energy, and time, and every one of them shows up in performance and cost.”

Title

Machine Learning Algorithm Map — Visual Framework and Classification Reflection

Objective

Build one visual framework that classifies at least eight to ten algorithms by learning type, application domain, real-world use, and how each one works, and that makes clear how the algorithms relate to and differ from one another.

What is it?

A three-part infographic. A color-coded concept map sorts twelve algorithms by how they learn and which model family they belong to. A connections panel shows how algorithms build on or differ from each other. A numbered comparison chart then gives the full details for each algorithm in one row.

Explore the Map

The same structure as the infographic. Pick a domain to see which algorithms are commonly used there, then select any algorithm to see how it works.

Process

The map was built in five steps. Select a step to see what happened in it.

Overall Progress

First version

A grid of twelve cards

Every card was accurate, but each algorithm stood alone. It presented twelve separate facts rather than one connected picture.

Final version

A concept map with a comparison chart

A three-level hierarchy, a numbered chart, and a relationship panel. The reader now sees a few decisions that sort every algorithm.

The biggest shift was checking the work against the goal, not only for accuracy. The goal was to show how algorithms relate, and only the rebuilt version did that.

Step-by-Step Key Takeaways

Value

This artifact shows that I can turn a long list of technical concepts into one connected, easy-to-scan picture. It defines clear rules for each category, makes the exceptions visible instead of hiding them, and shows relationships a simple list would miss.

It also connects directly to my work in financial services, where most data is tabular:

Random ForestFlagging unusual collateral and margin records
K-meansGrouping similar positions for review
TransformerThe language-model applications I build outside work

Knowing where each model belongs helps me choose a tool based on the problem rather than on what is popular.

Reflection — What I Learned

This assignment changed how I study the field. Instead of memorizing algorithms one at a time, I now look for the small number of decisions that sort all of them.

  • A few questions sort every algorithm: does it need labels, does it learn its own features, and where is it used today.
  • Real algorithms do not respect clean categories. A good framework defines each category by a test and shows the exceptions.
  • Transformers are self-supervised. During pretraining, the text itself supplies the answers.
  • Ensembles exist for a reason. A single decision tree can overfit, and many trees voting together reduce that risk.
  • AI, machine learning, deep learning, and generative AI are nested fields, and generative models create new content rather than classify existing content.
  • The right model depends on the problem, not on what is popular.
  • Classification design: building category rules I can apply the same way to every algorithm.
  • Visual communication: choosing a concept map for hierarchy and a chart for side-by-side comparison.
  • Self-critique: rebuilding a correct first version because it did not meet the real goal.
  • Source verification: using generative AI to clarify concepts, then checking its answers against the assigned resources.
  • Connecting ideas: linking Gini impurity from the fruit classification activity to why random forests exist.
  • Applied judgment: matching algorithms to real financial-services problems.

“Instead of memorizing algorithms one at a time, I started seeing a small number of decisions that sort all of them.”

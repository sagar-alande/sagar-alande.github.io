Title

Data Challenges in AI — Scenario-Based Learning Artifact

Objective

The objective of this activity was to strengthen my ability to handle real-world data challenges in machine learning in a more practical and decision-driven way. Instead of focusing only on techniques, I wanted to understand how to diagnose problems, choose the right strategy based on data behavior, connect technical decisions with business impact, and validate whether the chosen approach actually improves model performance.

What is it?

This artifact captures an interactive learning journey completed through an AI coaching system where each scenario presented a different data challenge commonly seen in machine learning projects. The scenarios were explored through step-by-step reasoning, follow-up questioning, and structured validation, making the experience feel closer to a real project discussion than a standard theory exercise.

Process

The learning followed a consistent pattern across all scenarios: understand → validate → decide → implement → evaluate → refine. Each scenario pushed the thinking one level deeper, moving from identifying the issue to choosing methods, validating outcomes, and refining the approach where needed.

Scenario 1

Missing Data

A housing price dataset contained missing values in critical features such as house size and number of bedrooms.

I began by quantifying nulls, checking missingness patterns, and understanding whether the issue was random, systematic, or related to upstream gaps. From there, I explored median imputation, grouped imputation, model-based imputation, and missingness indicators.

The key learning was that missing data should not be filled blindly. The method should depend on feature importance, scale of missingness, and whether the chosen strategy improves the model against a baseline.

Scenario 2

Noisy Data

A customer churn dataset contained noise in satisfaction ratings and usage metrics due to inconsistent scales, entry errors, and measurement variation.

Here, the focus shifted from “cleaning data” to first proving what was actual noise and what was valid business variation. I used ideas like distribution profiling, Z-score, IQR, and business validation before deciding whether to transform, cap, smooth, or remove values.

This scenario showed that over-cleaning can damage real signal. The better approach is to reduce the effect of bad data while preserving meaningful variation that the model should learn.

Scenario 3

Imbalanced Dataset

A loan default dataset had a strong class imbalance, with very few default cases compared to non-default cases.

I started by checking whether the imbalance was truly affecting model behavior instead of treating skew alone as the problem. From there, I explored oversampling, undersampling, SMOTE, class weights, and tree-based ensemble models.

The biggest shift came during evaluation. Accuracy was not enough. The discussion moved toward recall, precision, F1-score, confusion matrix, and business cost of missing a defaulter.

Scenario 4

Time-Series Challenges

A fintech DAU series had missing daily timestamps, weekly seasonality, and a slow upward trend.

This scenario required a different mindset because missing timestamps affect temporal structure, not just values. I first reindexed the series to a continuous timeline, then explored time-based interpolation, weekday-aware methods, and STL-style seasonal reasoning.

Validation became more advanced as well. I considered short and long hold-out gaps, MAE/RMSE, weekday-average preservation, lag-7 seasonality checks, and threshold-based pass/fail criteria.

Overall Progress

The strongest shift across this activity was the progression from simply identifying data issues to designing, validating, and iterating solutions. Instead of relying on one fixed method, I consistently used a baseline-first mindset, escalated only when needed, and connected technical methods with business impact — especially in finance-oriented scenarios.

Scenario-by-Scenario Takeaways

Missing Data

Diagnose: quantify nulls, inspect patterns (MCAR/MAR/MNAR), and check upstream pipeline issues.

Solutions: remove small non-critical gaps, median/grouped imputation, model-based imputation, missingness indicator.

Validation: baseline vs imputed models, cross-validation, RMSE/MAE/R².

Decision Rule: choose method based on feature importance and missingness scale.

Noisy Data

Diagnose: profile distributions, detect outliers using Z-score/IQR, check inconsistent scales, validate against business logic.

Solutions: scale/normalize, transform using log, cap or remove true errors, smooth continuous noise, preserve valid variation.

Validation: compare feature distributions, summary statistics, model metrics, and interpretability.

Imbalanced Data

Diagnose: quantify class distribution, build baseline, check business cost of errors.

Solutions: oversampling, undersampling, SMOTE, class weights, ensemble methods, anomaly-detection thinking where relevant.

Validation: precision, recall, F1-score, confusion matrix, cross-validation, overfitting checks on minority class.

Time-Series (Seasonality + Missing Timestamps)

Diagnose: reindex to continuous timeline, visualize, inspect trend/seasonality, review ACF/PACF.

Solutions: reindex + time-based interpolation as baseline, weekday-median, STL-style seasonal handling, gap-aware alternatives.

Validation: short and long hold-out gaps, MAE/RMSE, weekday-average comparison, lag-7 seasonality check, forward-chaining CV, thresholds.

Tools

Value

This artifact demonstrates a structured, production-oriented approach to handling machine learning data challenges. It highlights not only technical awareness, but also decision-making, validation discipline, and the ability to connect model performance with real business impact.

It reflects how I approach data problems in practical environments: start simple, validate assumptions, protect real signal, and use measurable evidence before moving to more complex methods.

Reflection — What you learned

This activity shifted my perspective from applying techniques to making informed decisions.

Key Learnings

  • Data issues must be validated before being treated as problems.
  • There is no single best method — the approach depends on context, scale, and impact.
  • Validation is critical — decisions should be based on measurable outcomes.
  • Business context plays a major role in technical decisions.
  • In time-series problems, preserving structure is more important than simply filling gaps.

Key Skills Developed

  • Problem scoping: I learned to always evaluate impact and business cost before taking action.
  • Method selection: I start with simple baselines and only move to complex solutions when needed.
  • Validation discipline: I rely on hold-outs, cross-validation, and distribution checks instead of single metrics.
  • Combining domain knowledge and statistics: I use business context to avoid removing valid signals.
  • Practical tooling mindset: I applied concepts using tools like Pandas, Scikit-learn, STL, SMOTE, and ensemble models.

Gaps & Next Steps

  • More hands-on practice: Run hold-out tests, imputation experiments, and model comparisons on real or synthetic datasets.
  • Advanced methods: Explore IterativeImputer, Balanced Random Forest, CatBoost/LightGBM with class weights, and time-series models like Prophet, ARIMA, and LSTM.
  • Monitoring: Design simple frameworks to track data drift and model degradation in production.
  • Ethics & privacy: Review fairness, compliance, and data privacy considerations, especially for financial datasets.

“Solving data challenges is not about applying techniques first. It is about understanding the data, validating assumptions, and making decisions that balance accuracy, stability, and real-world impact.”
